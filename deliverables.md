## Context the next session needs

**The package**: `tulpaObs` (renamed from `tulpaOcc` as Phase 5) is a unified
framework for hierarchical latent-state observation models on the `tulpa`
backend. The directory on disk is still `tulpaOcc/` and the GitHub repo URL
is still `gcol33/tulpaOcc`; only the package name itself was renamed.

**What already exists**:

- `tulpaObs` (this package, formerly `tulpaOcc`) — full-featured occupancy: single-season, dynamic,
  community, integrated, JSDM, ICAR/BYM2/GP/SPDE, Laplace + NUTS. ~132 tests.
- `tulpa` — engine. `tulpa_laplace()` (binomial/poisson/negbin/gaussian),
  `tulpa_em_laplace()` EM driver, `tulpa_nested_laplace()` (registry-based,
  470 lines, covers ICAR/BYM2/CAR/AR1/RW1/RW2/NNGP/HSGP/SPDE for the four
  families above), Polya-Gamma Gibbs, NUTS.
- `tulpaMesh` — SPDE mesh + precision builders.
- `INLAabun` — N-mixture via EM-around-INLA (reference for Phase 2).

**The driving use case**: `example/MOT_abund_data.Rmd` — vegetation cover
resurvey analysis (MOTIVATE / Pl@ntBert). Hurdle model: binomial on
`occur = cover > 0` + beta on `cover` (joint INLA fit with shared CAR spatial
field via `copy=..., fixed=FALSE`), with Mundlak within/between-plot time
decomposition. Phase 1's end target is to reproduce this on the tulpa
backend; Phase 1a starts with the simpler lognormal-positive separate-fit
variant that needs no tulpa edits.

**What's missing in tulpa for the joint MOT model**:

- Beta likelihood in `tulpa_laplace()` and `tulpa_nested_laplace()`.
- Joint multi-likelihood fits in `tulpa_nested_laplace()` (binomial + beta
  with shared latent fields via copy/scale).
- Lognormal as a likelihood label (currently fold to `family="gaussian"` on
  `log(y)`).
- `predict_at` row API on the nested-Laplace return.
- PC priors as defaults across all priors.

These are scheduled across Phase 1b, 1c, 1d. Phase 1a doesn't need any of
them.

### Acceptance criteria (tests/testthat/test-cover-hurdle-lognormal.R)

1. **Constructor**: `cover_hurdle(positive = "lognormal")` returns a
   `tulpa_obs_family` with `status = "working"`, `default_engine = "laplace"`.
2. **Round-trip on simulated data**: with N = 500, true `beta_occ = c(-0.5, 0.8)`
   and `beta_pos = c(-1.0, 0.3)`, the fit recovers each coefficient inside its
   ±2 SE interval at least 90% of the time across 20 replicates.
3. **Sigma recovery**: estimated `sigma_pos` within 20% of truth on a single
   N = 500 replicate.
4. **Prediction identity**: `predict(fit, newdata, type = "expected")` equals
   `predict(..., type = "occupancy") * predict(..., type = "conditional")`
   to within 1e-8.
5. **Zero-cover sites contribute only to occupancy**: a sanity check that
   `fits$pos` is fit on `sum(occur)` rows, not `N`.
6. **Family-error path**: `cover_hurdle(positive = "beta")` still errors with
   the Phase 1d scheduling message.
7. **Spatial smoke**: with `spatial_range = 0.3`, fit converges and the
   spatial hyperparameters in `fit$occ$hyperpar` are finite.

- `tests/testthat/test-laplace-beta.R` — recovers beta-distributed response
  parameters from simulation.

### Math (Math Ground First — write this down before coding)

Beta with mean parameterisation: `y ~ Beta(mu * phi, (1 - mu) * phi)` where
`mu = expit(eta)` and `phi > 0` is precision. Log-density:

```
log p(y | mu, phi) = lgamma(phi) - lgamma(mu*phi) - lgamma((1-mu)*phi)
                   + (mu*phi - 1) * log(y)
                   + ((1-mu)*phi - 1) * log(1 - y)
```

Score wrt eta (using `dmu/deta = mu * (1-mu)`):

```
d log p / d eta = phi * mu * (1-mu) * [digamma((1-mu)*phi) - digamma(mu*phi)
                                       + log(y) - log(1-y)]
```

Fisher information wrt eta (the IRLS weight):

```
W = phi * mu^2 * (1-mu)^2 * [trigamma(mu*phi) + trigamma((1-mu)*phi)]
```

(See Ferrari & Cribari-Neto 2004; Smithson & Verkuilen 2006.)

The phi parameter is a hyperparameter on the nested-Laplace outer grid in
1c. For 1b's single-Laplace path, fix phi or jointly profile via the EM
driver.

## Phase 1c — Joint multi-likelihood in tulpa nested Laplace

**Triggered after 1b passes review.** This is the big one — multi-session.

### What changes in `tulpa_nested_laplace()`

Current signature accepts a single response and a single latent prior block.
Extend to:

```r
tulpa_nested_laplace(
  responses = list(
    list(y = y_occ, n_trials = 1, X = X_occ, family = "binomial",
         latent_idx = list(spatial = idx_occ)),
    list(y = y_pos, X = X_pos, family = "beta", phi = NULL,
         latent_idx = list(spatial = idx_pos))
  ),
  prior   = list(...),     # shared latent field spec (BYM2 / CAR / SPDE)
  copies  = list(          # which latent blocks each response sees
    spatial = list(occ = list(copy_of = NULL, scale = 1),
                   pos = list(copy_of = "occ", scale = NULL))  # NULL = free
  ),
  ...
)
```

Inner Laplace at each θ-grid point now solves a joint mode-finding problem
with concatenated linear predictors and a stacked weight matrix W = blockdiag.
The shared field has one prior block; copied fields apply the
`Z_pos = scale * I` mapping at the design-matrix level.

### Files to touch in `tulpa`

- `R/nested_laplace.R` — multi-response dispatcher, copy/scale handling.
- `src/nested_laplace_joint.cpp` (new) — inner joint Laplace.
- `inst/include/tulpa/likelihood.h` — `LikelihoodBlock` struct holding
  family + linear-predictor slice + weight function.
- `tests/testthat/test-nested-laplace-joint.R` — binomial + beta on shared
  CAR field, recovers truth, matches INLA result on a tiny grid.

### Open math questions to settle first

1. Single shared spatial field vs two correlated fields (the INLA `copy`
   with `fixed=FALSE` learns a scale). The MOT example uses copy+scale.
   First implementation: copy+scale, scale prior `Normal(1, 0.5)` truncated
   to (0, ∞).
2. How to integrate the joint log-marginal over the θ grid when the two
   likelihoods have different hyperparameter sets (e.g. beta phi vs Gaussian
   sigma). Tentative: stack all hyperparameters into a single θ vector and
   build one CCD grid over the joint mode. Validate against MCMC.
3. Whether to require both responses to share latent_idx (every row appears
   in both) or allow disjoint indexing (positive part subsets occ rows).
   The MOT example is disjoint — pos uses only `occur == 1` rows. Must
   support disjoint.

## Engineering rules that apply

From `~/.claude/CLAUDE.md`:

- **Math Ground First**: for beta likelihood (1b), write down log-density,
  gradient, and IRLS weight on paper before coding. Don't reach for
  numerical Hessians.
- **No Dependency Shortcuts for Core Logic**: beta IRLS weights and the
  joint linear-predictor stack should be implemented natively, not
  delegated to `glmmTMB` even though glmmTMB is `Suggests:` in INLAabun.
- **Always Clean, Always Scaling**: when adding the cover hurdle, the
  `encode/fit/decode` shape becomes the template for all hurdle-style
  families (cover, zero-inflated counts, etc.). Don't make it
  cover-specific.
- **No Copy-Paste Across Specialized Functions**: when 1d extends 1a's
  cover hurdle to the joint engine, extract the shared linear-predictor
  construction into a helper, don't duplicate.
- **Surface Bugs in Dependencies**: any tulpa bug discovered in 1b/1c/1d
  gets a `gh issue create --repo gcol33/tulpa` *before* the workaround
  lands. Reference the issue from any skipped test.
- **Work on Main Branch by Default**: commit Phase 1a to `tulpaOcc/main`
  unless the user explicitly asks for a branch.
- **Try Before Deferring**: e.g. for the simulator's spatial draw, try the
  existing `tulpa::spatial_*` simulator before reaching for `MASS::mvrnorm`.

From this package's `CLAUDE.md`:

- **tulpaObs owns**: family encode/decode, family-specific S3, family-
  specific diagnostics.
- **tulpa owns**: engines, MI/Gibbs, generic S3, generic diagnostics.
- **Never pass `Rcpp::Nullable<T>` to header helpers** — MinGW crash. Not
  expected to be an issue in 1a (pure R), but watch for it in 1b.
